# netkeiba.com 無料公開データ重点調査

## 1. 目的・範囲

本書は、netkeiba.com の無料公開画面を JRA 予測研究のデータ源として使えるかを、項目、期間、URL/ID、取得方式、利用条件、Point-in-Time（PIT）、品質の面から再調査したものである。調査日は **2026-08-30** である。

> **同日追補:** 本書の一般的な新規取得・再利用条件の調査結果は維持する。一方、ユーザーは `/Users/zuoliao/Documents/GitHub/horse_codex/data/data` に既に存在するnetkeiba由来rawについて、本非公開・私的プロジェクト内での利用を明示的に承認した。この既存rawはMVP主データとして利用可能であり、新規scraping・公開・再配布は別判断である。詳細は[既存ローカルデータセット監査](local_existing_dataset.md)を参照する。

少数の公開ページ、利用規約、公式ヘルプ、料金比較、`robots.txt` だけを read-only で確認した。認証回避、内部 API の呼出し、網羅クロール、レート制限の負荷試験は行っていない。本書は法的助言ではなく、公式表示から確認できる事実とプロジェクト上の保守的判断を分ける。

### 調査した質問

- 無料・未ログインまたは無料 ID で、レース、馬、関係者、血統、オッズ、調教、ラップ、馬体重、払戻の何が見えるか。
- 1956 年以降という案内は、全項目・全出走馬が同じ完全性で揃うことを意味するか。
- URL や ID はどのように見え、公開 API または安定した機械可読仕様があるか。
- `robots.txt`、利用規約、二次利用方針、公式スクレイピング FAQ は何を許し、何を許していないか。
- 自動取得、保存、加工、個人 ML、派生物公開について、明示許諾を確認できるか。
- 差分取得、キャッシュ、PIT、過去オッズを再現可能な収集源として現実的か。

## 2. 結論要約

### 確認できた事実

- 競馬データベースは「1956 年以降にデビューした競走馬、レース、騎手、調教師、生産者、馬主」を検索できると案内する。レース詳細検索は、1956 年以降の中央競馬結果が対象と明記する。
- 未ログインで確認できる近年のレース結果には、競走条件、着順、枠・馬番、馬、性齢、斤量、騎手、走破時計、着差、通過順、上がり、単勝最終オッズ・人気、馬体重、調教師、馬主、賞金、払戻、コーナー通過、レースラップ等が表示される。
- 無料画面の公式比較では、リアルタイムの最新オッズ・自動更新、調教タイム、タイム指数、厩舎コメント、騎手・調教師等の詳細情報は無料対象外である。プラン・レース種別による範囲差がある。
- 公式ヘルプは、スクレイピングによる多数のリクエストがサービスへ支障を与えると判断した場合、予告なく通信制限し、解除依頼にも応じない場合があると明記する。数値閾値は公開していない。
- 2026-08-30 の少量確認では、`https://www.netkeiba.com/robots.txt` と `https://db.netkeiba.com/robots.txt` は HTTP 404 であり、その 2 origin に有効な robots 指示ファイルを確認できなかった。
- 今回の公式調査では、外部利用者向け公開 API、バルクダウンロード、差分フィード、履歴版 API、時系列オッズ archive、HTTP cache/SLA の契約仕様を確認できなかった。
- 利用規約は、サービスから得たデータ等を著作権法上の私的利用を超えて複製・販売・出版等へ使うこと、不特定・多数者が知りうる状態に置くこと、営業利用等を制限する。著作物に当たらないデータもサービス上は著作物とみなすと定める。
- 規約と公式 FAQ は、個人ローカル ML、組織的バルク保存、継続自動取得を包括的に許諾していない。

### 解釈

- 無料画面は目視照合には非常に有用だが、長期再現可能な ML データ供給契約ではない。
- `robots.txt` が 404 であることは、スクレイピング、保存、学習利用の許諾ではない。利用規約、権利、負荷、認証、個別コンテンツ条件は別に適用される。
- 公式 FAQ はスクレイピングを一律に「許可」または「禁止」とは書かず、利用者自身に規約適合性確認を求め、サービス支障時の通信制限を明示している。したがって「低速なら許可」「個人なら許可」とは推論できない。
- 画面 URL と ID は観察できるが、外部 API 契約ではなく、文字コード、HTML、JavaScript、プラン表示、内部 endpoint の変更に弱い。

### 推奨

- netkeiba 無料画面を MVP の自動収集源にしない。無料予測trackはJRA公式成績PDFを条件付き主候補とし、厳密PIT・市場trackはJRA-VAN/JV-Linkを有料fallbackとする統合結論に従う。
- netkeiba は、少数レコードの目視比較、古い競馬史の存在確認、JRA-VAN の例外監査に限定する。
- 独自データが不可欠なら、取得方法、リクエスト量、保存、加工、ML、クラウド、共同利用、派生特徴・予測・モデル公開を具体化して株式会社ネットドリーマーズへ書面照会する。
- 許諾を得るまで、内部 Ajax endpoint、認証済み画面、通信制限回避、網羅列挙を利用しない。

## 3. 無料表示・有料表示の項目整理

無料表示は、代表ページを未ログインで目視できたことと、公式プラン比較の「無料」列を根拠にする。キャンペーンによる一時開放や検索エンジンの断片表示は、恒常的無料提供の根拠にしない。

| レース条件 | 日付、場、開催回日、クラス、年齢・性・指定条件、斤量条件、発走、距離、コース、天候、馬場 | 近年ページで広く表示。古い年代は項目縮小 | 結果ページの天候・馬場は事後確定値 |
| 出走・結果 | 着順、枠、馬番、馬、性齢、斤量、騎手、時計、着差、通過、上がり、調教師、馬主、賞金 | 近年は全出走馬表。1956 年の代表的払戻一覧では上位 3 頭中心 | 対象レース結果はラベルのみ |

| 騎手・調教師等 | 基本プロフィール、表彰、leaderboard、検索結果、レース表からの ID link は一部公開 | 全詳細・条件分析は有料比較表で無料対象外 | 現在通算を過去特徴にしない |

| 予想オッズ | 発売前に netkeiba 独自 AI の単勝予想オッズが表示される場合あり | 全レース対象との画面説明 | JRA 市場オッズではない。主モデルへ混入禁止 |

| 走行データ/個馬ラップ解析 | Master 等の上位機能。2025 年以降対象との画面表示例あり | 平地中央等の対象制約 | race-level 公式ラップと混同しない |

### 無料の意味

- 未ログインで閲覧できる公開 DB ページがある。
- 一部機能は無料 ID が必要であり、たとえばお気に入りや勝ち馬サーチには登録条件・件数制限がある。
- 「無料 Web で表示される」は、バルク取得、恒久保存、データベース複製、ML への投入が許諾されることを意味しない。
- 料金・プラン・キャンペーンは変わる。2026-08-30 に確認した Web 比較は Premium 640 円/月、Super Premium 1,390 円/月または年額 13,900 円であり、アプリ経由は Premium 690 円/月、Super Premium 1,490 円/月等と異なる。

## 4. 履歴期間と網羅性

### 4.1 公式に確認できた範囲

- DB トップは、1956 年以降にデビューした競走馬、レース、騎手、調教師、生産者、馬主を検索可能と案内する。
- レース詳細検索は「1956 年以降の中央競馬のレース結果」が対象と明記する。
- 1956-12-30 の日付別一覧には、中央の複数場・各競走が表示される。
- 1956-01-14 の代表的払戻一覧は、競走条件、上位 3 頭、騎手、勝時計/着差、人気、当時の払戻を表示する。
- 1986-10-05 の代表的レース詳細は、全出走馬型の表に通過、上がり、単勝、人気、馬体重等を表示する。
- 2000-03-25 の代表的レース詳細は、レースラップと払戻を表示する。

### 4.2 見つからなかった保証

- 1956 年以降の全開催・全競走・全出走馬・全列が完全であるという completeness guarantee。
- 馬体重、単勝最終オッズ、上がり、通過、race-level lap の正確な収録開始日と欠損率。
- 地方・海外を中央と同一品質・同一開始年で網羅する保証。
- 訂正履歴、旧版、削除、データ提供元別 provenance の行単位記録。
- UI で現在表示される内容が将来も同じ URL・列・プランで提供される保証。

### 解釈

「検索対象 1956 年以降」は discoverability の説明であって、機械学習用 rectangular dataset の完全性仕様ではない。学習開始年や field coverage を、公開ページの存在だけから決めてはならない。

## 5. URL・ID・画面内部構造

### 5.1 少量観察で確認した URL

| 対象 | 例 | 観察結果 |
|---|---|---|
| DB トップ | `https://db.netkeiba.com/` | 検索、各 entity、race DB への入口 |
| 日付別レース | `/race/list/20240622/` | `YYYYMMDD` 形式の日付 path |
| classic race detail | `/race/202405030710/` | 中央で 12 桁の race ID が見える |
| modern result | `https://race.netkeiba.com/race/result.html?race_id=202607020407` | query parameter で race ID |
| odds | `/odds/index.html?race_id=...&type=b1` | `type` で表示式別が変わる画面 |
| horse | `/horse/2012102013` | 近代馬で 10 桁風の ID |
| pedigree | `/horse/ped/2012102013/` | horse ID を path に使用 |
| jockey | `/jockey/record/05339/` | entity path に別桁 ID |
| detailed search | `/horse/list.html?...`, `/?pid=race_list&...` | GET parameter 型検索画面 |

12 桁 race ID は中央の年・場・回・日・競走番号に見えるが、公式外部仕様は確認できない。推測分解を契約にせず opaque identifier として扱う。古い馬には `000a...` のような英数字 ID の表示例もあるため、「全 horse ID は 10 桁数値」と仮定できない。

### 5.2 API に見えるものの扱い

代表的 classic race HTML の source には、画面を構成する Ajax/JSONP endpoint 名と race ID parameter が埋め込まれていた。しかし、次は確認できない。

- 外部開発者向け API documentation、認証キー、version、schema、rate limit、SLA。
- その endpoint を画面外の収集に使う許諾。
- endpoint、parameter、response が継続する保証。

したがって、ブラウザ内部 endpoint を「公開 API」と呼ばず、直接呼び出さない。URL が推測可能、HTML に endpoint が見える、検索エンジンが index する、のいずれも API 利用許諾ではない。

### 5.3 技術上の脆弱性

- classic DB は EUC-JP の HTML を返す代表例があり、modern race UI は JavaScript 前提である。
- 同じ race が classic `db` と modern `race` の異なる UI で表示される。
- 有料列は空欄、`**`、アイコン、campaign 表示になることがあり、HTML 列の存在はデータ利用可能性を意味しない。
- class 名、HTML 列、動的 endpoint、会員 gating は製品更新で変わりうる。

## 6. robots.txt、レート制限、キャッシュ、差分取得

### 6.1 robots.txt

#### 事実

- 2026-08-30 に `https://www.netkeiba.com/robots.txt` を GET すると 404 Not Found だった。
- 同日に `https://db.netkeiba.com/robots.txt` も 404 Not Found だった。
- robots は origin ごとのため、この結果だけで `race.netkeiba.com` 等の別 origin を説明できない。

#### 解釈

- 404 は、その 2 origin に robots directive が見つからなかったという技術的観察にすぎない。
- robots はアクセス許諾、著作権ライセンス、会員規約、データ再利用ライセンスではない。`Disallow` がないことを許可と解釈しない。

### 6.2 公式スクレイピング FAQ

#### 事実

公式 FAQ「データベースの閲覧ができない・通信制限がかかった（スクレイピングについて）」は、次を説明する。

- スクレイピングによる多数のリクエストを確認し、サービスへ支障があると判断した場合、予告なく通信制限することがある。
- 制限解除を依頼しても解除できない場合がある。
- サービス運営を妨害する等の規約禁止事項には、スクレイピングにより運営へ支障を来す場合も含まれる。
- スクレイピングが規約に抵触しないかは利用者自身で確認するよう求める。

数値リクエスト数、時間窓、`429`/`403` 等の挙動、解除期間、許容 crawler は公開していない。

#### 解釈

- 公式 FAQ は、スクレイピング一般を積極的に許諾していない。
- 同時に、「あらゆる自動取得を一律禁止」ともこの FAQ 単独では書いていない。問題のない件数を推測して収集設計することはできない。
- 複数年の全レースを再現可能に集める処理は多数リクエストになりやすく、数値基準不明・解除保証なしのサービスを基盤依存先にする運用リスクは高い。

### 6.3 cache / delta / throughput

#### 確認できなかったもの

- 公式の `ETag`/`Last-Modified` 保証、conditional GET 契約、cache TTL。
- 日付または cursor による変更差分 feed、訂正一覧、webhook。
- bulk export、page size 上限、安定した pagination contract。
- 機械取得 SLA、許容 requests/second/day。

#### 現実性評価

日付一覧や連番に見える race ID から新規ページを推測することは技術的には考えられるが、許諾、欠番、訂正、取消、再開催、地方 ID、HTML 変更を解決しない。既取得ページをローカル cache すれば負荷を減らせるが、そもそもの大量取得・保存・加工許諾を与えるものではない。

利用許諾が得られた場合でも、公式に提供される許容頻度、User-Agent/連絡先、差分方法、再試行、保管期間、訂正通知を先に合意すべきである。現状で rate-limit を実験的に探らない。

## 7. 利用規約・著作権・公開方針

### 7.1 利用規約

#### 事実

- 第 14 条は、承認がある場合を除き、サービスから得たデータ等を著作権法上の私的利用を超えて複製、販売、出版のために使うことを制限する。
- 同条は、著作物に当たらないデータ等もサービスを通じて得たものは著作物とみなし、不特定または多数が知りうる状態に置く行為は目的を問わず私的利用外とみなす。
- 第 15 条は、サービスを使った営業活動、営利目的利用、その準備を、個別承認がない限り制限する。
- 第 16 条は、無権限アクセス、設備・サービスの利用や運営に支障を与える行為等を禁止する。
- 規約改定のお知らせは、現行調査で参照した規約が 2022-04-01 に改定されたことを示す。

#### 不確実性

- 規約は「ML」「model training」「dataset」「cache」「research database」「スクレイピングによる少量取得」を個別に定義していない。
- 個人の完全ローカル・非公開 ML が私的利用に含まれるか、自動取得と長期保存を伴っても同じか、学習済みモデルがデータ等に当たるかについて、公式回答を確認できなかった。

### 7.2 情報提供元と正確性

#### 事実

- DB トップは、JRA、ジャパン・スタッドブック・インターナショナル、日本軽種馬協会、中央競馬ピーアール・センター等から許諾を受けた情報等を提供すると表示する。
- レース/オッズ画面は、結果・成績・オッズ等を主催者発表と照合するよう注意を表示する。

#### 解釈

- 提供元が netkeiba へ許諾したことは、netkeiba 利用者にデータ再取得・再配布権を再許諾したことを意味しない。
- netkeiba は信頼できる二次表示・照合源だが、主催者発表を source of truth とするよう自身で注意している。

### 7.3 二次利用ガイド

#### 事実

公式の画面キャプチャガイドは、ルール内で出馬表、レース結果画面、競走馬 DB 等のスクリーンショットを個人サイト、ブログ、指定 SNS/動画サイト等で使うことを認める。ログアウト状態で有料コンテンツを含めないよう求める。一方、レース/調教映像、予想家の予想、外部ニュース、コラム、競馬新聞、調教タイム、厩舎コメント等は二次利用不可と明記する。

#### 解釈

- これは所定のスクリーンショット利用に限定された公開方針で、表データの抽出、網羅 download、DB 化、ML dataset 作成の許諾ではない。
- 収益化された動画等でキャプチャを使える場合があることを、データの商用利用許諾へ一般化しない。

## 8. 個人研究・保存・ML 利用の判断

| 行為 | 公式確認 | 本プロジェクトの判断 |
|---|---|---|
| ブラウザで無料ページを目視 | 提供目的内 | 可。少量の調査・照合 |
| 許可範囲の画面キャプチャ | 二次利用ガイドあり | ガイド条件内のみ |
| 少量ページを手作業で研究メモ | 私的利用の可能性 | 必要最小限。再公開しない |
| 自動的な少量取得 | 明示許諾なし。負荷時制限 FAQ あり | 許諾済みとみなさない |
| 全 JRA 履歴の自動収集 | 明示許諾なし、多数リクエスト化 | 採用しない |
| HTML/表の恒久 DB 保存 | 明示範囲不明 | 書面確認前は採用しない |
| 特徴量化・個人ローカル ML | 明示回答なし | JRA-VAN の公式回答を netkeiba へ流用しない。書面確認 |
| 生/派生データの共同利用 | 私的利用外になりうる | 採用しない |
| 学習データ、予測、モデルの公開 | 明示回答なし | 公開可否を個別確認 |
| 商用利用・準備 | 原則制限、承認制 | 通常利用から除外 |
| 通信制限回避、認証回避 | 許諾なし。運営支障・無権限アクセスの危険 | 禁止方針 |

「私的利用なら法律上必ず ML 可能」「著作権のない事実だから規約外」「無料ページだから保存自由」といった判断は、本調査の公式資料からは導けない。

## 9. PIT と historical odds

### 9.1 オッズ

#### 事実

- 最新オッズ・自動更新は有料プラン機能である。
- 発売前の画面には netkeiba 独自の AI 予想オッズが表示され、発売後に実際のオッズへ切り替わると案内される。
- 近年の結果 DB は各馬の確定単勝オッズ・人気と公式払戻を表示する。
- 過去 race の odds 画面を少量確認すると、画面枠が残っていても値が `---.-` となる代表例が複数あった。これは観察結果であり、全期間の仕様保証ではない。
- 公式資料から、任意の過去時点のオッズ snapshot、発表 timestamp、取得可能期間、interval、訂正を再取得する archive 仕様を確認できなかった。

#### 結論

- netkeiba の無料結果 DB は final win odds/払戻の事後診断には使える表示だが、現実的な T-10 等の historical odds backtest を作る根拠にならない。
- 有料リアルタイム画面を契約しても、それは履歴 API・保存許諾・長期 archive の保証ではない。
- 独自 AI 予想オッズを JRA market odds と誤認しない。

### 9.2 その他の PIT

- horse profile の現在調教師、通算賞金、通算成績、産駒成績等は、過去予測時点より後の情報を含む。
- race result の天候、馬場、馬体重、取消後頭数は、結果画面からは発表時刻を再現できない。
- 現在の調教ページは過去調教を表示しても、各 record が当時何時に公開されたか、後日訂正されたかの archive 仕様を示さない。
- race 検索は馬齢・賞金を現在表記へ統一すると明記しており、制度当時の raw 表記をそのまま保持した歴史版ではない。
- 現在画面に revision ID、`published_at`, `valid_from/to`, old version がないため、厳密な as-of join を保証できない。

結論として、netkeiba の現在表示から構築できるのは主に retrospective な latest-known history であり、transaction-time PIT history ではない。

## 10. データ品質と ID 対応

### 10.1 品質上の利点

- JRA 等から許諾を得た情報を統合し、中央・地方、馬、血統、関係者を人が検索しやすい形にしている。
- 近年結果ページは、学習候補となる基本項目を一画面で横断確認できる。
- 古い中央競馬まで検索でき、歴史的存在確認や JRA-VAN の例外照合に有用である。

### 10.2 品質上の制約

- 自身が主催者発表との照合を求めており、公式 source of truth ではない。
- 項目開始年、欠損率、訂正、遅延、完全性の machine-readable specification がない。
- 旧制度を現在表記へ正規化する場合があり、当時値と current-normalized value を区別できない。
- 公式事実、netkeiba 独自指数、AI 予想、プロ評価、ユーザー投稿が同一 UI に並ぶため、provenance を誤る危険がある。
- campaign・会員 rank により見える列が変わり、検索 index の断片が無料通常画面と一致しない場合がある。

### 10.3 ID

- race、horse、jockey 等に URL ID があるため、netkeiba 内の link key としては有用である。
- しかし外部向け ID specification、JRA-VAN/JRA/JBIS ID との公式 crosswalk、ID 再利用/統廃合/訂正方針は確認できない。
- 古い horse ID は英数字、近代 horse ID は数値風であり、型や桁を固定しない。
- race ID の見た目から場・回・日を復号しても、それを公式仕様とせず、元の opaque string とページ上の race metadata を併記する。
- 氏名・馬名だけの fuzzy join は改名、同名、全角半角、旧字体、地方・海外馬で誤対応しうる。公式 ID bridge がなければ手動監査が必要である。

## 11. 取得・差分運用の現実性

### 技術的評価

| 観点 | 評価 |
|---|---|
| 初回全履歴 | ページ数が大きく、多数 request・通信制限・欠損・HTML change の危険。非現実的 |
| 毎週差分 | 日付/出馬表 URL は観察可能だが、訂正 feed がなく、完了判定不能 |
| race-day 更新 | dynamic UI、有料 gating、更新時刻差、通信制限。PIT 取得源として不適 |
| cache | ローカル cache は負荷を減らすが、保存許諾と訂正検知を解決しない |
| historical odds | final win odds 以外の時系列 archive を確認できず、不適 |
| schema stability | classic/modern、EUC-JP/JS、会員列により低い |
| entity join | netkeiba 内では可能だが、公式 crosswalk 不在 |
| auditability | source revision/published timestamp がなく低い |

### 提案

1. 自動収集の実装に進まない。
2. 無料画面は、公式 JRA/JRA-VAN で解釈が難しい 1 レース・1 馬の目視調査に限定する。
3. netkeiba 固有の調教・指数・コメントが必要になった時だけ、公式問い合わせで bulk/API/研究契約の有無を確認する。
4. 許諾が得られない場合、無料データの技術的取得可否に関係なく不採用とする。
5. 公式データ比較では、netkeiba ID と JRA-VAN key を別列で保持し、公式 crosswalk がない対応には confidence と根拠を残す。

## 12. 既存 `data_sources.md` との整合・矛盾

### 整合した点

- 「1956 年以降にデビューした馬等を検索可能」は公式 DB トップで再確認できた。
- 調教タイム、独自指数、コメント等は有料機能である。
- 公開一括 API、PIT snapshot、時系列オッズ download 仕様、自動取得・保存・ML の包括許諾を確認できない。
- 規約は私的利用外、公開、営業利用等を制約する。
- 書面許諾なしで MVP の大量取得源にしないという既存判断は維持される。

### 補足・修正が望ましい点

1. 既存表の netkeiba「オッズ ○（当日表示）」は、無料/有料の区別がない。**リアルタイム最新オッズ・自動更新は無料対象外**で、無料で安定確認できるのは主に結果表の final win odds と払戻である。
2. 既存表の「調教 ○（有料）」は正しいが、無料は明確に対象外であり、Premium/Super、重賞・新馬/全レース等で範囲差がある。
3. 既存文書のアプリ価格 600/1,200 円という別ページ表示と、今回確認した現行アプリ 690/1,490 円、Web 640/1,390 円は一致しない。価格は channel・page・campaign により変動するため、固定値ではなく契約画面を都度確認する。
4. 既存文書は「スクレイピング許諾を確認できない」と記載し、これは正しい。今回、さらに公式 FAQ で、多数 request が支障と判断されると予告なく通信制限し、解除しない場合があることを確認した。一方、FAQ を「全スクレイピングの明示的一律禁止」と言い換えるのも不正確である。
5. 1956 年という期間は検索対象の開始であり、全 field の開始・完全性ではない。古い代表ページは近年より情報が少ない。

重大な方針矛盾はない。今回の深掘りは、既存の「目視比較に限定し、自動収集源にしない」という判断を強化する。
