# 無料優先MVP：データ源の横断的批判レビュー

## 1. 目的と結論

本書は、追加調査の [netkeiba](free_data_netkeiba.md)、[国内無料ソース](free_data_japan_sources.md)、[公開データセット/API](free_data_public_datasets.md) を横断し、**無料優先MVP**という新しい制約下で、JRA公式成績PDFを主データ源候補とする案を批判的に再評価したものである。調査日は **2026-08-30**。大量取得、スクレイパー実装、認証回避は行っていない。本書は法的助言ではない。

### 結論

- **JRA公式成績PDFは、無料候補の中ではJRA予測ベースラインの主データ源として最も妥当である。** 2002年以降の全成績を主催者自身が開催回または開催日ごとにまとまったPDFとして公開し、履歴特徴、ラベル、最終市場診断に必要な主要結果項目を一つの公式系統から得られる。HTMLページの網羅クロールより、リクエスト数、URL安定性、一次性、再検証性の面で優れる。
- ただし、これは **「無条件で自動取得・恒久保存・ML利用できる公式オープンデータ」だという結論ではない。** JRAはPDFを一般ダウンロード用に公開しているが、公開API、オープンデータライセンス、機械取得rate、数値データの保存・加工・MLに関する包括許諾は確認できない。プロジェクトの保守的なlicense gateでは、体系的な一括取得を始める前に用途を書面照会する。
- 無料構成で直ちに成立するのは、**少数PDFを用いた項目・抽出可能性の検証、設計、手動照合**までである。個人ローカル研究として必要最小限の情報解析が著作権法30条の4の対象となり得ることは、JRAによる個別許諾とは別論点であり、契約、サーバ負荷、データベースの市場、公開・共同利用まで一括して解決しない。
- 成績PDFから作る長期学習データは **PIT-C（event reconstruction）** である。`P(win)` とランキングの仮説比較には使えるが、当時の訂正前版、取消、騎手変更、馬体重公表時刻、当日馬場、締切前オッズを再現しない。したがって長期の実行可能ROIを証明しない。
- 既存結論の「JRA-VAN/JV-Linkを主ソース」は誤りになったのではない。既存結論は **規約根拠、機械可読性、PIT、ID、運用再現性を優先**した判断で、新方針は **料金0円をMVPの第一制約**に追加した。よって、無料予測ベースラインはJRA PDF、厳密PIT・市場評価・調教を必要とする段階ではJRA-VAN、という二段階に修正するのが整合的である。

## 2. JRA公式成績PDFを主候補とする根拠

### 2.1 確認できた事実

- JRA FAQは、Webのレース結果を1986年以降、成績PDFを2002年以降掲載すると明記する。2000年以前のWeb結果は不完全または表示ルールが異なる場合がある。
- 年度別ページは2002年についても全10場の各開催PDFを列挙する。公式説明は「2002年以降のレース成績をすべて掲載」とする。
- 成績表の見方は、発走定刻、負担重量、馬体重・前走比、着差、単勝オッズ・人気、払戻、的中票数・総票数、ハロンタイム、通過タイム、コーナー通過順位、所属、取消等を定義する。実際の成績表にはレース条件、出走馬、騎手、調教師、着順、走破時計等も含まれる。
- PDFは年・競馬場・開催回/開催日を単位とし、例えば近年には `.../report/2025/2025-5tokyo8.pdf`、2002年には `.../report/2002/1-sapp.pdf` のようなURLで公開される。年度によって命名・文書単位が同一とは限らない。少量のHEAD確認では `Content-Length`、`Last-Modified`、`ETag`、`Accept-Ranges` が返った。
- JRAの `robots.txt` は全ユーザーエージェントに対して `Disallow:` が空である。一方、これはアクセス、保存、加工、MLの法的・契約的許諾ではない。
- JRAの「ご利用に際して」はサイト情報の予告なし変更・削除を留保し、映像・音声・画像・記事等の著作権保護を明記する。数値成績の自動取得・ローカルDB化・MLを明示的に許可または禁止する記載は、今回の公式資料では確認できない。
- 現行の開催場別出馬表PDFは一般公開されるが、掲載期間は8週間である。長期履歴は提供されず、今後の版を自ら受信時刻付きで保存しなければprospective PITは蓄積できない。

### 2.2 技術面の評価

| 観点 | 評価 | 留意点 |
|---|---|---|
| 一次性 | 高 | 主催者公式。民間表示差は公式で裁定する |
| 期間 | 中～高 | 全成績PDFは2002年以降。1986～2001はWeb検索だが別方式・不完全性あり |
| 網羅取得のリクエスト数 | 高 | レースごとでなく開催回/開催日をまとめたPDFなので、HTML全レース巡回より大幅に少ない |
| URL安定性 | 中～高 | 年度・開催回/開催日単位で比較的規則的。年代で命名差があり、公式API/SLAではなく変更可能 |
| 差分・cache | 中 | ETag/Last-Modifiedは観測できる。保証されたdelta APIではない |
| 構造化容易性 | 低 | 表形式だがPDF。特に古いPDFはテキスト抽出順が大きく崩れる例があり、OCRまたは座標ベース抽出と原本照合が必要。列順、改行、フォント、注記、同着・取消・障害等でも誤抽出しうる |
| ID | 低 | 安定した外部仕様のhorse/person IDや公式crosswalkがない。名前だけの結合は監査が必要 |
| 訂正・版 | 低 | 旧版・revision ID・公開時刻の保証がない。再取得時の差分は自前検知が必要 |
| 長期PIT | 低 | 結果版からのイベント順再構築に限る |
| 当日運用 | 低～中 | 出馬表PDFは8週間。オッズ、変更、馬体重を一つの版付きfeedとして取得できない |

### 2.3 何を「主データ源」と呼べるか

JRA PDFを主ソースと呼べる範囲は、**長期no-odds予測ベースラインの履歴・ラベル主系統**である。次は主張しない。

- 公式に許諾された自動バルクAPIである。
- 予測時点の全情報を再現するPIT-A/Bデータである。
- 実行可能な締切前オッズbacktestができる。
- 血統、調教、馬具、コメント、完全な地方歴を単一ソースで得られる。
- 2002年以前と2002年以降で同じ列・完全性を保証できる。

したがって、無料MVPの名称も `JRA PDF PIT-C prediction baseline` のように、情報品質を含めて明示するのがよい。

## 3. A/B/C判定

判定はソース名だけでなく**行為**に対して行う。無料閲覧可能性と、継続自動取得・保存・加工MLの許諾を混同しない。

### A. 無料で直ちに使える

| 対象 | 直ちに許容する範囲 | 根拠・限界 |
|---|---|---|
| JRA成績PDF | ブラウザからの少数・手動ダウンロード、項目定義確認、抽出PoC、目視照合 | 公式がPDFダウンロードを予定して公開。体系的全履歴取得・長期DB化はBへ分離 |
| JRA現行出馬表PDF | 少数の予測時点仕様確認、手動のprospective sample | 8週間のみ。取得時刻を自ら記録してもJRAによる版履歴保証ではない |
| 気象庁CSV | 規約と取得上限に従った気象補完、出典・加工表示、品質flag保持 | 公共データ利用規約が明確。JRA公式weather/goingの代替にはしない |
| 合成データ | parser/schema/test設計 | 第三者datasetをfixtureへコピーせず、架空レースを明示的に生成する |
| JRA・JBIS・netkeiba・競馬ラボの公開画面 | 少数レコードの人手照合と項目意味の確認 | 数値を組織的に転記・蓄積する運用へ拡張しない |

ここでいうAは、法的無リスクを保証しない。JRA PDFの少数ローカル情報解析については著作権法30条の4が適用され得るが、JRAの個別許諾、規約、データベース市場、アクセス負荷、成果公開を一括して許可する条文ではない。

### B. 書面確認後のみ採用

| 対象 | 確認が必要な行為 | 暫定判断 |
|---|---|---|
| JRA成績・出馬表PDF | 2002年以降の体系的取得、定期巡回、raw長期保存、全文抽出、特徴量化、個人ML、訂正前版保持、モデル・予測公開 | **無料主候補。最優先でJRAへ照会** |
| JRA HTML/当日オッズ | 定期snapshot、馬体重・取消・騎手変更の保存、内部endpoint利用 | URL/API仕様とrateがない。PDF許諾と別に明示確認 |
| netkeiba | 自動取得、バルク保存、HTML/内部endpoint、ML、派生物・予測公開 | 技術的には豊富だが、規約・通信制限・PIT/API不在により許諾前は主ソースにしない |
| JBIS | 血統・繁殖・セールの自動取得、加工ML、長期保存 | 規約制限、`Crawl-delay: 600`、`/csv/`除外。許諾後も補助のみ |
| 競馬ラボ | レース結果、ラップ、コメント等の自動取得・保存・ML | 複写転載制限、API/rate/PIT不在。許諾後も増分項目だけ評価 |
| NAR公式ZIP/CSV | 自動DL、2分版の長期保存、加工ML、JRA馬とのID対応 | 公式DLだがrobotsがDL pathを除外し、規約は無断複製を制限。地方歴補助のみ |
| JRHA等 | セール価格等の一括取得・加工ML | 二次利用条件、ID対応、履歴完全性を確認してから独立feature群にする |

JRAへは、対象PDF一覧、想定総件数と毎週件数、直列取得、User-Agent/連絡先、conditional GET、raw保存期間、ローカル個人ML、特徴・モデル・予測の非公開/公開、将来商用化を分けて質問する。回答が得られない場合、プロジェクトの保守的方針では自動バックフィルを開始しない。

### C. 不採用

| 対象・行為 | 理由 |
|---|---|
| 無許諾のnetkeiba/JBIS/競馬ラボ全履歴scraping | 閲覧可能性、規則的URL、robots不在、低rateは利用許諾ではない |
| 競馬ブックのプログラム取込 | 規約がプログラムによるデータ取込を明示的に禁止 |
| Kaggle/GitHub/Hugging FaceのJRA再配布データ | uploaderのCC0/CC BY/Apache表示は上流データの取得・再配布権を証明しない。出所不明またはnetkeiba scrape、PIT不明 |
| scraper OSSの出力・既成archive | code licenseは対象サイトのデータをライセンスしない |
| 海外データをJRA学習値へ直接統合 | 市場、制度、馬場、出走集団が異なる。schema/方法論sandbox以外には使わない |
| 最終オッズによる過去bet選択 | 購入時点で未知のためlook-ahead。最終払戻による事後精算とは別 |
| 認証・有料wall・bot制限・robotsの回避 | 明示的no-go。負荷制限を探る試験も行わない |

## 4. 無料構成のfeature coverage

### 4.1 JRA成績PDFから取得・導出できる候補

| 群 | 生項目・派生例 | PIT評価 |
|---|---|---|
| レース条件 | 日付、場、開催、R、surface、距離、クラス/条件、負担重量条件、頭数 | ターゲット結果版はPIT-C。制度変遷を保持 |
| runner | 枠、馬番、馬名、性齢、斤量、騎手、調教師、所属 | 最終結果版のfield。取消・変更前版なし |
| 結果ラベル | 着順、同着、取消・除外、時計、着差、賞金 | 対象レースではlabel専用 |
| 過去走フォーム | 過去N日/全履歴の着順、着差、時計、上がり、通過順、馬体重、休養間隔、連闘/詰め間隔 | 過去レースだけをevent順にjoinすればPIT-Cで利用可 |
| pace/course適性 | race-levelラップ、上がり、コーナー位置、距離・surface・場・回り別集計 | 個馬区間タイムではない。条件別sample不足に注意 |
| field/strength | 頭数、相対斤量、過去対戦、forward-only Elo/BT、相手強度 | 相手のtarget後成績を使わない |
| jockey/trainer履歴 | cutoff前の騎乗・管理成績、条件別率、組合せ統計 | 生IDではなく名称起点。改名・同名・所属変更を監査 |
| 当日状態 | 馬体重・増減、天候、馬場 | 値は結果PDFにあるが発表時刻なし。`T_prevday`へ使用不可、`T_close`でもPIT-C限定 |
| 最終市場・精算 | 最終単勝オッズ・人気、払戻、票数 | 事後診断・精算専用。主予測入力とbet選択に使わない |

気象庁CSVを加えると、最寄り観測所の降水、気温、風等を独立feature群として追加できる。競馬場との距離、観測時刻、品質flag、遡及訂正を保持し、JRA公表馬場を置換しない。

### 4.2 無料構成で不足または困難

- 全馬の構造化された坂路・ウッド調教時計、追切内容、調教時の馬体状態。
- 2002年以前を同一PDF schemaで扱える全JRA結果と、項目別完全性仕様。
- 永続horse/jockey/trainer ID、公式crosswalk、血統master、出生・生産・セールの一貫した履歴。
- 取消、除外、騎手変更、発走時刻変更、馬体重、馬場の時刻付き全revision。
- 長期の締切前オッズsnapshot、票数推移、snapshot→最終価格slippage。
- 結果PDFで不足する完全血統、地方・海外歴、馬具、故障・休養理由、厩舎コメント、パドック情報。
- providerが保証するschema、delta、訂正履歴、機械取得SLA。

これらは「モデルに必須」とは限らない。まず無料coreだけのbaselineを作り、各不足群の有料増分を一仮説ずつ比較する。

## 5. PITとhistorical oddsの限界

### 5.1 無料長期履歴でできること

- 2002年以降のイベント順に、各targetより前の公式確定結果だけからフォーム、適性、rating、騎手・調教師集計を再構築する。
- no-oddsの`P(win)`、LambdaRank、確率校正、ランキング、subgroup診断を比較する。
- 最終オッズから事後の市場順位・暗黙確率を計算し、**final-odds oracle diagnostic**としてモデルとの関係を見る。
- モデル選択とbet選択に結果・最終オッズを使っていない固定選択について、公式払戻で実現損益を精算する。ただし価格条件付き戦略ではない。

### 5.2 無料長期履歴でできないこと

- `T-10`等で表示されていたオッズを使ったEV閾値選択の再現。
- 取消・変更・馬体重・馬場・オッズを同じcutoffにそろえたdecision snapshot。
- snapshot時に買えた価格の固定。JRAはpari-mutuelであり、表示オッズ自体も最終払戻倍率を保証しない。
- PDFの最終単勝オッズを過去時点へ代入した「実行可能ROI」の主張。

### 5.3 無料で今後できる可能性

JRAの書面回答が取得・保存を認める場合、現行出馬表、馬体重、変更、馬場、単勝オッズを `retrieved_at` とcontent hash付きでprospectiveに保存し、PIT-Aに近いshadow datasetを蓄積できる。JRAが正式な配信時刻・revision IDを付与するわけではないため、これは自分が観測した版であり、過去に遡って作れない。許諾、capture failure、遅延、staleness、発走変更を別途監査する。

## 6. JRA-VANを導入する増分

| 課題 | 無料JRA PDF | JRA-VAN/JV-Linkの増分 | 残る限界 |
|---|---|---|---|
| 機械取得 | PDF解析・非契約URL | 公式JV-Link、仕様書、データ種別、更新処理 | Windows/COM中心、月額2,090円 |
| 期間 | PDF 2002+ | 主なJRA履歴1986+ | 古い項目欠損・開始年差 |
| ID/schema | 安定ID・schemaなし | race/runner/entity keyと固定長仕様 | コード変遷の監査は必要 |
| 血統/master | 限定 | 競走馬、繁殖、血統、生産、セール等 | snapshot以前の版は完全でない |
| 調教 | 構造化全馬履歴なし | 坂路2003+、ウッドは2021年以降の東西別開始 | coverage差・欠測あり |
| 当日PIT | 最終結果中心 | 出馬表、変更、馬体重、天候馬場、速報結果 | 過去の全transaction版を無期限保証しない |
| 時系列odds | 長期は最終値だけ | 単複枠・馬連を約5～10分間隔、発表時刻付き | オンライン保持保証は1年。長期化には今後の自前保存が必要 |
| 許諾根拠 | ML・自動取得の明示なし | 特定条件の個人ローカル研究について公式回答あり | 公開、共同利用、cloud、商用は別確認 |

JRA-VANは無料構成の弱点を大きく減らすが、1986年からの完全な取引時点履歴や長期締切前オッズを後から自動的に与えるものではない。導入初日からPIT-A snapshotを版管理する必要がある。

## 7. 既存結論との整合と修正案

### 7.1 矛盾の正体

既存の [data_sources.md](data_sources.md) と [research_conclusions.md](research_conclusions.md) は、JRA-VANを「取得方法と個人研究利用の根拠が最も明確な主ソース」とした。これは一次情報に整合する。一方、新しい依頼は「無料を最大限活用」をMVPの優先条件にした。評価関数が変わったため、単一の順位表で一方を誤りとするのではなく、次の二軌道にする。

1. **Free prediction track:** JRA成績PDF 2002+を中心にしたPIT-C、no-odds予測baseline。書面確認までは少数手動PoCに留める。
2. **Executable market / data-quality track:** JRA-VAN/JV-Link、またはJRAから許諾されたprospective snapshots。PIT-A/B、調教、ID、変更、時点oddsを扱う。

無料trackで予測手法を棄却・採択することはできるが、実行可能市場評価を代替しない。JRA-VANは「最初から必須」から「無料coreの限界を越える最優先upgrade」に位置付けを変える。

### 7.2 research_conclusionsへ反映すべき決定

- MVP主データ源を「JRA-VAN一択」から「**無料予測baselineはJRA公式成績PDF、厳密PIT/市場trackはJRA-VAN**」へ修正する。
- JRA PDFは2002+、PIT-C、no-odds prediction限定と明記する。
- 自動backfillはJRAへの書面照会、または法務・リスク受容を明示したproject decisionをgateにする。
- netkeibaは豊富さを理由に無料主系統へ昇格させず、許諾取得後のみ補完候補とする。
- historical final oddsと締切前snapshotを別table・別metric・別用語にする。
- 無料で取得困難なfeatureを、JRA-VAN導入後の一群ずつのablation対象にする。

## 8. 推奨する次の調査・decision gate

実装前に、次の順で不確実性を解消する。

1. JRAへ、成績PDFと現行出馬表/オッズの自動取得、取得頻度、長期保存、個人ローカルML、成果公開について書面照会する。
2. 許諾を待つ間は、2002年・制度変更年・最新年から各1開催程度を**手動で**選び、PDFのテキスト層、列変化、同着、取消、障害、開催中止、欠測の抽出可能性だけを監査する。大量取得はしない。
3. 無料baselineのfeature contractを、`core_result_history`、`race_context`、`form_workload`、`field_strength`、`weather_jma`、`final_market_oracle`に分離する。
4. JRA回答が不許可または不明確で、全履歴自動化が必要なら、無料制約と再現性のどちらを優先するかを人間が決定する。JRA-VANが最小コストの正規代替である。
5. 締切前オッズは過去へ遡れないため、取得許諾が得られた日からshadow captureを開始する。それまでは実行可能ROIを評価項目にしない。
